## 1. 서론

### 1.1 문서 목적 및 범위
본 문서의 목적은 쿠팡, 네이버쇼핑, 11번가 등 여러 이커머스 플랫폼에 분산된 장바구니 품목을 하나의 통합 플랫폼에서 조회 및 관리할 수 있도록 구축된 'One-Cart(원카트) 통합 장바구니 시스템'에 대한 블랙박스 테스팅을 수행하고 그 결과를 기록하는 데에 있다. 본 문서에서는 프로젝트의 테스트 기준, 범위, 구체적인 테스트 케이스 및 최종 합격 여부를 명시한다.

### 1.2 프로젝트 개요
국내 주요 이커머스 플랫폼의 장바구니 데이터를 크롤링 및 Open API(OAuth 2.0)를 통해 실시간으로 수집하고, 사용자에게 통합된 단일 뷰(개별 정렬, 총 결제 금액 합산, 최저가 비교 알림, 예산 제어, 공유 바구니 기능 등)를 제공하는 모바일 웹/앱 서비스를 안정적으로 구동 및 검증하는 시스템을 구축한다.

### 1.3 용어 정의

| 용어 | 설명 |
| :--- | :--- |
| 서버사이드 | 서버 측 시스템을 뜻하며, 본 프로젝트에서는 데이터베이스와 크롤링 모듈, 외부 쇼핑몰 API 통신 및 연산 기능을 수행한다. |
| 클라이언트 | 사용자 눈에 보이는 시스템을 뜻하며, 본 프로젝트에서는 모바일 웹 시스템과 안드로이드/iOS 하이브리드 앱 시스템을 뜻한다. |
| 장바구니 동기화 | 외부 이커머스 플랫폼의 장바구니 데이터를 크롤링 또는 API를 통해 One-Cart 시스템 내부 데이터 포맷과 실시간으로 일치시키는 작업 |
| 공유 바구니 | 여러 플랫폼의 상품을 모아 타인과 링크 형식으로 공유할 수 있는 위시리스트 기능 |

## 2. 테스트 개요

### 2.1 테스트 범위
테스트는 시스템 내부 명세 및 소스코드를 모른다는 가정하에 외부 인터페이스와 기능 요구사항에 초점을 맞춘 **블랙박스 테스트**로 이루어진다. 테스트 범위는 아래와 같다.

| 범위 | 내용 |
| :--- | :--- |
| Web / App 기반 시스템 | Ⅰ. 브라우저 및 모바일(Android/iOS) 환경 동작 정확성 확인<br>Ⅱ. UI/UX 반응형 레이아웃 및 사용성 요구사항 충족 확인 |
| Database | Ⅰ. 웹/앱 간 사용자 장바구니 변경 사항 실시간 연동 시험<br>Ⅱ. 암호화된 개인정보 및 연동 토큰 데이터 입출력 확인 |
| External Interface | Ⅰ. 주요 쇼핑몰 OAuth 2.0 인증 및 API 연동 데이터 변환 정확성 검증<br>Ⅱ. 웹 크롤러 모듈의 세션 유지 및 예외 처리 검증 |

### 2.2 테스트 항목 및 통과 기준

**기능별 테스트 항목**
| 기능별 테스트 항목 | 통과 기준 |
| :--- | :--- |
| 회원 및 인증 기능 | 일반 회원가입 및 소셜 간편 로그인(Google, Kakao)이 성공하고 마이페이지에서 연동 계정이 정상 출력된다. |
| 쇼핑몰 연동 기능 | 외부 계정 연동 및 연동 해제가 정상 작동하며, 연동 실패 시 사용자에게 실패 사유 알림이 제공된다. |
| 통합 장바구니 조회 기능 | 연동된 전 쇼핑몰 품목이 단일 뷰에 노출되며, 배송비 포함 합산 금액 계산 및 수량 수정/삭제가 반영된다. |
| 최저가 비교 및 알림 | 타 플랫폼 최저가 비교 정보가 표기되고, 설정 목표가 이하 도달 시 푸시 알림 및 외부 상품 링크 이동이 성공한다. |
| 예산 관리 기능 | 월별 쇼핑 예산 설정이 가능하고 장바구니 총액이 예산 초과 시 시각적 경고 및 비율 그래프가 정상 표기된다. |
| 위시리스트 공유 기능 | 공유 바구니 링크가 정상 생성되며, 비로그인 사용자도 링크를 통해 열람 및 자기 장바구니 추가가 가능하다. |

**비기능별 테스트 항목**
| 비기능별 테스트 항목 | 통과 기준 |
| :--- | :--- |
| 호환성 테스트 | Android 8.0 이상, iOS 13.0 이상 및 주요 브라우저(Chrome, Safari 등)에서 정상 작동한다. |
| 성능 테스트 | 동시 접속 사용자 1,000명 이상 환경에서 모든 사용자 요청에 대해 3초 이내로 응답한다. |
| 보안 테스트 | 전송 데이터의 HTTPS 암호화 처리 및 DB 내 개인정보/토큰 데이터의 AES-256 암호화 저장 여부를 검증한다. |

## 3. 테스트 케이스

### 3.1 테스트 케이스 선정
테스트 케이스는 본문 2.2의 기능별/비기능별 테스트 항목 및 우선순위(상) 요구사항을 기반으로 선정하였으며, 시스템 내부 동작 프로세스를 배제하고 철저히 사용자 시점과 인터페이스 연동 성공 유무에 중점적인 테스팅 케이스를 도출하였다.

### 3.2 테스트 케이스 유형
- 회원 인증 및 인증 유효성 검증을 위한 문자열 입력 테스트 케이스
- 외부 API 연동 및 웹 크롤링 데이터 정합성 확인을 위한 동작 동기화 테스트 케이스
- 대용량 데이터 연산(합산, 예산 제어) 및 예외 처리를 위한 데이터 흐름 테스트 케이스
- 플랫폼 간 공유 및 비로그인 접근 권한 제어를 위한 접근 제어 테스트 케이스
