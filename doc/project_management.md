# [프로젝트 계획서 v1.1] One-Cart (원카트): 통합 장바구니 시스템
**Unified Shopping Cart System (USCS)**

---

## 1. 개요 (Introduction)

### 1.1 문서의 목적
본 문서는 'One-Cart' 프로젝트의 개발 전반에 대한 계획을 수립하고, 개발 공정을 정의하여 프로젝트를 성공적으로 완수하는 것을 목적으로 합니다.

### 1.2 프로젝트 개요
- **명칭:** One-Cart (원카트) / Unified Shopping Cart System (USCS)
- **설명:** 쿠팡, 네이버, 11번가 등 여러 이커머스 플랫폼에 흩어져 있는 장바구니 품목을 한곳에서 조회하고 관리하는 통합 플랫폼입니다.
- **핵심 기능:** 플랫폼별 데이터 실시간 동기화, 최저가 비교 및 알림, 통합 결제 금액 계산기 등.

### 1.3 관련 문서, 용어 및 약어
- **관련 문서:** 프로젝트 정의서 v1.0
- **USCS:** Unified Shopping Cart System의 약자.
- **Crawling:** 외부 웹사이트에서 데이터를 자동으로 수집하는 기술.

## 6. 데이터 관리 계획 (Data Management Plan)

### 6.1 개요
One-Cart는 복수의 이커머스 플랫폼에서 장바구니 데이터를 수집·통합하는 서비스 특성상, 데이터의 정합성과 흐름을 명확히 정의하는 것이 핵심입니다. 본 절에서는 데이터 수집부터 사용자 노출까지의 전체 흐름과 Firebase 기반의 데이터 구조 설계 방향을 기술합니다.

### 6.2 데이터 흐름도
데이터는 다음 4단계의 흐름을 따라 처리됩니다.

| 단계 | 처리 주체 | 설명 |
|---|---|---|
| 1단계 | 크롤링 모듈 (Python) | 쿠팡, 네이버, 11번가 등 대상 플랫폼에서 장바구니 데이터를 수집합니다. |
| 2단계 | 데이터 정제 모듈 (Python) | 수집된 원시 데이터를 정규화하고 플랫폼 간 통일된 스키마로 변환합니다. |
| 3단계 | Firebase Firestore | 정제된 데이터를 저장하고, 실시간 동기화를 통해 앱과 연동합니다. |
| 4단계 | 안드로이드 앱 (Kotlin) | Firebase로부터 데이터를 수신하여 통합 장바구니 UI로 사용자에게 표시합니다. |

### 6.3 데이터 스키마 설계
Firebase Firestore의 컬렉션 구조는 다음과 같이 설계합니다.

| 컬렉션/필드 | 타입 | 설명 |
|---|---|---|
| users/{userId} | Document | 사용자 정보 및 연동 플랫폼 목록 저장 |
| cartItems/{itemId} | Document | 통합 장바구니의 개별 상품 문서 |
| &nbsp;&nbsp;└ platformId | String | 데이터 출처 플랫폼 식별자 (예: 'coupang', 'naver') |
| &nbsp;&nbsp;└ productName | String | 상품명 |
| &nbsp;&nbsp;└ price | Number | 현재 플랫폼에서의 가격 (단위: 원) |
| &nbsp;&nbsp;└ quantity | Number | 장바구니에 담긴 수량 |
| &nbsp;&nbsp;└ updatedAt | Timestamp | 마지막 동기화 시각 |
| &nbsp;&nbsp;└ imageUrl | String | 상품 썸네일 이미지 URL |

### 6.4 데이터 동기화 전략

| 전략 항목 | 내용 |
|---|---|
| 동기화 주기 | 앱 실행 시 즉시 동기화 + 백그라운드 주기 동기화 (30분 간격) |
| 충돌 처리 | 플랫폼 원본 데이터를 기준으로 덮어쓰기(Last-Write-Wins) 방식 적용 |
| 오프라인 지원 | Firebase 오프라인 캐시를 활용하여 네트워크 미연결 시에도 최근 데이터 조회 가능 |
| 오류 처리 | 크롤링 실패 시 해당 플랫폼 항목에 stale 표시, 재시도 큐에 등록 |

### 6.5 데이터 보안
- Firebase Security Rules를 통해 인증된 사용자만 본인의 장바구니 데이터에 접근 가능하도록 제한합니다.
- API Key 및 크롤링 인증 정보는 GitHub Private Repository의 환경 변수로 관리하며 코드에 직접 포함하지 않습니다.
- 장바구니 데이터는 개인정보를 직접 포함하지 않으나, userId 단위로 암호화하여 저장합니다.
