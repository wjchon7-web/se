# [프로젝트 계획서] One-Cart (원카트): 통합 장바구니 시스템

---

## 1. 개요 (Introduction)

### 1.1 문서의 목적
본 문서는 'One-Cart' 프로젝트의 개발 전반에 대한 계획을 수립하고, 개발 공정을 정의하여 프로젝트를 성공적으로 완수하는 것을 목적으로 합니다.

### 1.2 프로젝트 개요
- **명칭:** One-Cart (원카트) / Unified Shopping Cart System (USCS)
- **설명:** 쿠팡, 네이버, 11번가 등 여러 이커머스 플랫폼에 흩어져 있는 장바구니 품목을 한곳에서 조회하고 관리하는 통합 플랫폼입니다.
- **핵심 기능:** 플랫폼별 데이터 실시간 동기화, 최저가 비교 및 알림, 통합 결제 금액 계산기 등.

### 1.3 관련 문서, 용어 및 약어
- **관련 문서:** 프로젝트 정의서 v1.0
- **USCS:** Unified Shopping Cart System의 약자.
- **Crawling:** 외부 웹사이트에서 데이터를 자동으로 수집하는 기술.

## 2. 개발 계획 (Development Plan)

### 2.1 프로세스 모델 및 개발 방법론
본 프로젝트는 1인 개발 환경으로 수행되며, 요구사항 변경 가능성과 기능의 점진적 개선을 위해 Agile 기반의 Scrum 방법론을 채택합니다. 팀 단위 회의 대신 개발자가 직접 Sprint 계획을 수립하고 수행 결과를 점검하는 방식으로 진행합니다.

### 2.2 작업 분할도 (WBS)

| 단계 | 작업 내용 |
|---|---|
| 환경 설정 | 개발 환경 구성 및 오픈 API 분석 |
| 크롤링 모듈 | 쇼핑몰 데이터 크롤링 모듈 개발 |
| DB 연동 | Firebase 데이터베이스 연동 및 동기화 구현 |
| 프론트엔드 | UI/UX 디자인 및 안드로이드 앱 개발 |
| 테스트 및 배포 | 통합 테스트, 버그 수정 및 최종 배포 |

### 2.3 소요 자원
- **인력:** 천원재 (1인 개발)
- **예산:** 오픈소스 라이브러리 및 클라우드 무료 티어(Firebase 등) 활용으로 비용 최소화.

### 2.4 개발 일정

| 기간 | 활동 |
|---|---|
| 1~2주차 | 요구사항 정의 및 시스템 설계 |
| 3~6주차 | 주요 기능 구현 (Kotlin / Python) |
| 7주차 | 품질 검수 및 최종 배포 |

## 3. 조직 구성 (Organization)

### 3.1 팀 구조
본 프로젝트는 1인 개발 프로젝트로 수행되며, 단일 개발자가 전체 개발 과정을 담당합니다. 효율적인 관리를 위해 프로젝트 관리, 개발, 테스트의 역할을 논리적으로 분리하여 수행하는 중앙집중형 구조를 채택합니다.

### 3.2 역할 및 책임

| 역할 | 책임 |
|---|---|
| Project Manager (PM) | 프로젝트 일정 수립 및 전체 진행 관리 |
| Developer | 안드로이드 앱 개발 및 API 연동 |
| QA | 기능 테스트 및 품질 관리 |

※ 1인 개발 프로젝트이므로 위 역할 전체를 단일 개발자가 수행합니다.

## 4. 기술 관리 계획 (Technical Management)

### 4.1 버전 관리
- **소프트웨어:** 파일명 맨 앞에 버전을 기재하며, GitHub를 통해 소스 코드를 관리합니다.
- **문서:** 파일명 맨 뒤에 날짜를 기재하고, 클라우드 및 GitHub에 병행 저장하여 제/개정 이력을 관리합니다.

### 4.2 형상 관리
- **Naming 규칙:** `[프로젝트명]문서명_YYMMDD_Doc-v버전` 형식을 적용하여 산출물을 식별합니다.

### 4.3 기술 관리
1인 개발 환경이므로 기능 변경 시 개발자가 단독으로 변경 사유와 내용을 판단합니다. 변경 전/후 내용은 반드시 문서 및 Git 커밋 이력으로 보존합니다.

## 5. 품질 관리 계획 (Quality Control)

### 5.1 품질 목표
- 모든 지원 플랫폼의 장바구니 데이터 동기화 오차율 1% 미만 유지.

### 5.2 개발 점검 방법 및 주기
1인 개발 프로젝트이므로 별도의 팀 미팅은 진행하지 않습니다. 대신 개발자가 매주 1회 정기적으로 개발 진행 상황을 자체 점검합니다.
- **점검 시간:** 매주 1회
- **점검 내용:** 개발 진행 상황, 기능 구현 여부, 오류 발생 여부, 다음 작업 계획
- **점검 방법:** 개발자가 직접 진행 상황을 기록하고 필요한 경우 개발 계획을 수정합니다.

### 5.3 품질 관리 적용 기법
- 단위 테스트 및 통합 테스트 수행.
- 각 Sprint 종료 후 기능 완성도 자체 평가 및 개선 사항 도출.

### 5.4 리스크 관리
- 쇼핑몰 보안 정책 변경에 따른 크롤링 차단 리스크 대비 (대체 API 확보).
